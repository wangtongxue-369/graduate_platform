# 全站主题重设计规范

日期：2026-06-02
主题：全站主题系统优化与视觉重设计

## 1. 目标

在保留当前产品信息架构、页面结构和品牌主色方向的前提下，对全站主题系统进行一次明显但可控的视觉重设计。

本次目标不是局部修色，而是把当前“主题能力已接入、但视觉系统仍然割裂”的状态，升级为一套更成熟、更一致、更适合长期扩展的产品化主题系统。

本次重设计重点解决以下问题：

- 浅色主题整体偏灰、偏雾，首屏对比度不足
- 卡片、标签、按钮、浮层之间缺少稳定的层级关系
- 大量局部样式仍然依赖硬编码浅色背景和透明品牌色，深浅色切换后容易割裂
- 偏好面板具备功能，但视觉语言与全站其余区域不完全一致
- 深色模式已可用，但仍更像“覆盖式适配”，而不是“同一产品的另一套主题映射”

## 2. 设计方向

本次采用的视觉方向为：`冷静科技感`

核心特征如下：

- 以雾白、冷灰青、深墨色建立稳定的产品基底
- 保留品牌青绿色，但仅用于关键交互、状态强调和焦点引导
- 弱化大面积朦胧奶白渐变，减少“展示页滤镜感”
- 强化文字、卡片、浮层和操作控件之间的层级关系
- 让首页更像成熟的多入口平台，而不是偏海报式的展示页

一句话概括：
从“柔和展示感”调整为“专业平台感”，让界面更清楚、更稳、更像一个持续演进的 Web 产品。

## 3. 范围

本次优化包含：

- 全站主题 token 体系重整
- 浅色 / 深色主题映射统一
- 首页导航、首屏、主要卡片系统的视觉重构
- 偏好面板的视觉重新融入
- 常见基础控件样式统一：
  - 按钮
  - chip / tag / 筛选项
  - 下拉与模态浮层
  - 输入框 / 文本域 / 搜索框 / 滑块
- 代表性页面验证与收敛：
  - `/`
  - `/login`
  - `/community`

本次不包含：

- 页面业务结构重写
- 全站国际化文案改写
- 新 UI 框架引入
- 对所有历史页面逐页做独立视觉翻新

## 4. 视觉原则

### 4.1 清晰优先

优先保证主标题、正文、辅助信息、按钮和卡片边界在首屏即可形成清楚的阅读关系，不再依赖大面积低对比雾光来制造“高级感”。

### 4.2 统一优先

把当前散落在页面各处的浅色块、透明品牌底色、局部渐变、独立阴影风格，收束进一套统一的语义样式系统。

### 4.3 品牌节制

品牌青绿色不再大面积铺底，而是用于：

- 主按钮
- 选中态
- 关键状态标签
- 焦点描边
- 图表或进度条主进度

这样可以提升品牌识别，同时避免整页“到处都是浅青底”的廉价感。

### 4.4 深浅色同源

浅色和深色不是两套互相独立的视觉稿，而是同一组语义 token 在不同亮度语境下的映射。目标是让用户感受到“同一个产品的两种主题”，而不是“浅色版 + 修补过的暗色版”。

## 5. 主题系统重构

### 5.1 语义层划分

主题 token 统一收束为以下几类：

- `基础背景层`
  - 页面主背景
  - 局部环境光背景
- `表面层`
  - 默认卡片表面
  - 强调卡片表面
  - 浮层 / 面板表面
- `文字层`
  - 主文字
  - 次级文字
  - 弱提示文字
- `品牌层`
  - 主品牌色
  - 品牌高亮色
  - 品牌反差文字色
- `边界层`
  - 常规边框
  - 强调边框
  - 焦点边框
- `状态层`
  - 成功
  - 警告
  - 危险
  - 信息
- `效果层`
  - 默认阴影
  - 浮层阴影
  - 环境光 / 柔和高亮

### 5.2 目标变化

从当前“token 已有，但大量组件仍有独立写死值”的状态，调整为：

- 页面主背景、卡片、浮层尽量由语义变量驱动
- 常见交互态不再直接依赖零散的 `rgba(...)` 和硬编码十六进制颜色
- 页面强调区域使用同一套高亮逻辑，而不是每个模块单独决定一组渐变

## 6. 页面层级模型

本次首页和全站公共区域统一采用四层层级结构：

### 6.1 页面底层

- 作用：提供稳定、干净的空间基底
- 处理：以冷白或深墨背景为主，只保留轻量氛围光感
- 目标：不干扰内容识别

### 6.2 产品外壳层

- 作用：承载导航、站点身份、关键入口
- 处理：让导航更像应用壳层，而不是漂浮装饰块
- 目标：提高平台感与稳定性

### 6.3 内容承载层

- 作用：承载卡片、数据块、列表、模块说明
- 处理：用统一卡片语言拉开默认态与强调态
- 目标：让用户快速理解阅读顺序和交互区域

### 6.4 控制与浮层

- 作用：承载偏好面板、下拉、模态框、局部控制组件
- 处理：统一为一套 elevated surface 语言
- 目标：确保偏好面板不再像“额外插入的玻璃浮层”

## 7. 组件重设计范围

### 7.1 顶部导航

调整方向：

- 从展示型轻漂浮导航，转为更稳定的产品式导航条
- 强化当前页状态识别
- 统一导航链接、按钮、下拉的背景与交互反馈

设计目标：

- 更清楚地表达“这是平台外壳”
- 在浅色与深色下都保持稳定存在感

### 7.2 Hero 首屏

调整方向：

- 降低背景雾光权重
- 提升主标题与说明文字对比度
- 强化 CTA 按钮的主次关系
- 重新整理信息卡片的表面层级

设计目标：

- 让首页第一屏更像成熟产品首页
- 让信息和动作更容易被第一时间识别

### 7.3 卡片系统

统一出至少以下几类卡片：

- `默认卡`
- `强调卡`
- `数据卡`
- `面板卡`

每类卡片统一：

- 圆角策略
- 边框强度
- 阴影层级
- hover / selected / accent 反馈方式

设计目标：

- 避免每个模块都像独立设计
- 提升页面内的秩序感和可维护性

### 7.4 按钮与标签系统

统一以下元素的交互语言：

- 主按钮
- 次按钮
- ghost 按钮
- chip
- tag
- 筛选按钮

设计目标：

- 主按钮更有行动感
- 非主按钮不再显得发灰或无力
- 选中态在偏好面板和业务页面之间保持一致

### 7.5 浮层系统

统一以下浮层组件视觉语言：

- 偏好面板
- 下拉菜单
- 模态框
- 局部弹层

设计目标：

- 统一背景材质、边框、阴影、模糊和内边距逻辑
- 让控制面板成为全站系统的一部分

### 7.6 表单与输入区

统一以下控件：

- 输入框
- 文本域
- 搜索框
- select
- range slider

设计目标：

- 统一白底 / 深底输入控件的视觉基线
- 保证焦点态、禁用态、占位文字和边界清晰可读

## 8. 偏好面板优化原则

当前偏好面板功能有效，本次重点优化其视觉归属感。

改造方向：

- 保留全局入口位置和核心交互逻辑
- 让入口按钮更像全站控制入口，而不是单独彩色悬浮球
- 让面板背景、边界、排版、选中态与全站卡片系统对齐
- 让滑块、主题选项、语言选项拥有统一的选择器风格

不改动的核心能力：

- 主题切换
- 字体大小滑块
- 语言模式切换
- 本地持久化

## 9. 深色模式策略

### 9.1 总原则

深色模式采用“深墨青基底 + 抬升式表面层”，不使用纯黑背景，也不依赖过强发光边框。

### 9.2 重点要求

- 主文字对比度清楚
- 次级文字可读但不刺眼
- 卡片边界在深色下依然可辨
- 品牌青绿色作为强调时不过曝
- 导航、卡片、浮层三者之间层级依旧稳定

### 9.3 交互一致性

以下状态在深浅色中保持同样的逻辑：

- hover
- active
- selected
- focus
- disabled

目标是让用户感受到主题变化，而不是交互规则变化。

## 10. 实现边界

本次实现优先以以下文件为主题收口点：

- `frontend/src/index.css`
- `frontend/src/App.css`
- `frontend/src/components/PreferencesPanel.jsx`

必要时可做少量接入性调整，但不以重写页面结构为目标。

实现优先级建议如下：

1. 重建主题 token 与浅深色映射
2. 统一导航、按钮、卡片、浮层的公共视觉语言
3. 优化首页 Hero 和核心模块区
4. 同步偏好面板视觉
5. 检查 `/login` 与 `/community` 的共性组件是否继承新主题

## 11. 验证策略

### 11.1 视觉验证

至少检查以下页面：

- `/`
- `/login`
- `/community`

每个页面至少验证：

- 浅色主题
- 深色主题
- 偏好面板打开状态

### 11.2 验收重点

验收时重点观察以下四项：

- 对比度是否清楚
- 卡片层级是否稳定
- 偏好面板是否融入全站
- 深色模式是否仍像同一产品

## 12. 风险与取舍

风险：

- `App.css` 当前存在较多历史硬编码颜色，完全收口到 token 需要分阶段推进
- 某些历史页面可能会先得到“明显改善但未完全统一”的结果
- 如果在不调整结构的前提下追求过强视觉差异，容易再次引入局部特例

取舍：

- 本轮优先建立稳定的主题系统和公共组件语言
- 优先解决首页、登录页、社区页这类代表性页面的统一感
- 不追求一次性逐页精修所有历史页面

## 13. 成功标准

- 首页从“偏灰、偏雾、层级不稳”转为“清楚、专业、可读”
- 导航、卡片、浮层和控制组件共享一致的视觉语言
- 偏好面板在视觉上融入全站而不是独立存在
- 深色模式具备完整产品感，不再像补丁式适配
- 后续页面可以继续沿用本次整理出的主题 token 和组件层级扩展
