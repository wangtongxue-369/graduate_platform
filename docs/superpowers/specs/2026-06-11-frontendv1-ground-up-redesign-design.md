# frontendv1 推倒重来的角色化前端重设计

日期：2026-06-11

主题：放弃当前 `frontendv1` 延续旧 `frontend` 门户骨架的设计思路，基于后端真实功能结构，为游客、学生四方向、管理员重新定义更商业化、更有辨识度、逐层深入的前端体系。

替代关系：本设计替代 [2026-06-10-frontendv1-role-based-main-station-design.md](E:\GAODUAN\GithubProject\OtherProject\graduate_platform\docs\superpowers\specs\2026-06-10-frontendv1-role-based-main-station-design.md) 中仍偏“主站入口规划”的部分。旧文可保留为背景资料，但后续实现以本文为准。

## 1. 背景与问题判断

当前 `frontendv1` 已经开始按角色分流，也做了游客态、登录弹窗、社区预览等改造，但用户仍明确感知到它“几乎和旧 frontend 一样”。这个判断成立，原因不在颜色和文案，而在骨架。

现状的同源问题主要有四个：

- 首页和主站仍然采用“hero + stats + 模块卡片 + CTA”的门户模型。
- 多数功能仍被表述为“进入某个模块”，而不是“完成某个工作”。
- 不同方向的页面器具过于相似，很多地方只是换标题，没有换交互语言。
- 深页虽已有返回条，但上层结构仍然像“平铺的功能卖场”，所以整体观感依旧接近旧站。

用户本轮要求不是继续精修这套门户，而是彻底换骨架：

- 根据后端功能重新组织前端，不沿用旧首页结构。
- 功能必须逐层深入，不能多个摊在一个页面里。
- 每层都要有明显返回路径和状态提示。
- 游客保留社区、题库等公共能力，不是假空白身份。
- 同一品牌下，游客、学生、管理员和学生四个方向都要有不同主站效果。
- 风格参考 Hugo 主题的内容秩序感，但最终要更像成熟商业产品，而不是模板站或 AI 常见布局。

## 2. 设计锚点

### 2.1 产品主题

我将本次前端重设计锚定为：

- 主题：毕业路径决策平台
- 受众：正在做路径选择和执行管理的大学生，以及负责治理平台内容与数据的管理员
- 页面单一职责：让用户先进入正确语境，再进入正确工作面，而不是先看到一堆功能名词

### 2.2 核心设计判断

本次前端不再做“统一卡片门户”，而改成“统一品牌下的不同工作器具系统”。

统一的是：

- 品牌色、字体、分隔语言、提示语风格、返回逻辑

变化的是：

- 每个角色和方向的中央工作面器具
- 首页的布局密度
- 重点信息的呈现方式

### 2.3 视觉取向

借鉴对象不是某个具体 Hugo 主题页面，而是它们常见的三个优点：

- 目录秩序清楚
- 版心克制
- 内容与结构分隔明显

本设计不会照搬博客样式，而是把这种秩序感嫁接到工作流前端上。

## 3. 视觉与品牌系统

### 3.1 色彩系统

使用一套克制的商业化冷暖配色，避免廉价渐变和大块高饱和背景：

- `Graphite` `#1C2430`：主文本、主分隔、管理员重区
- `Mist Slate` `#6F7C8E`：次级文本、说明、辅助图层
- `Paper Ash` `#EEF1EC`：页面基底、内容区背景
- `Copper Clay` `#A66A4C`：重点动作、签名色、登录和提交动作
- `Harbor Blue` `#2E5B74`：学生流程强调色
- `Signal Olive` `#5F7355`：完成态、资料沉淀类模块

### 3.2 字体系统

- 展示标题：`Source Han Serif SC`
- 正文与导航：`IBM Plex Sans`
- 数据、标签、步骤标识：`IBM Plex Mono`

原因：

- 黑体加无衬线是最容易落回普通站点的组合。
- 这里用宋体标题，不是为了文艺，而是为了让“路径、目录、档案、卷宗”这套气质站得住。
- 数据区再用等宽体，能自然拉开内容叙述和状态摘要的层次。

### 3.3 版式语言

整站采用“左索引、中工作面、右上下文”的三栏原则，但不是每页都硬拆三栏，而是按页面性质做偏移：

- 游客层：左目录窄、中内容宽、右侧做轻量提示抽屉
- 学生层：左阶段导航固定，中间工作面最强，右侧做状态摘要
- 管理员层：左队列、中央工单列表、右处置面板

### 3.4 签名元素

全站只保留一个强辨识度元素：`纵向阶段脊线`

表现方式：

- 在主站和深页的左侧，不用传统侧边栏，而是做成带编号和状态点的“阶段脊线”
- 它既是导航，也是返回路径，也是当前层级提示
- 不同方向替换脊线文案，但结构一致

这个元素比再做一个花哨 hero 更有辨识度，也更贴合“逐层深入”的要求。

## 4. 后端驱动的信息架构

本设计完全服从现有后端功能，不伪造对称能力。

### 4.1 公共层

游客与登录用户都可直接到达：

- 社区：帖子列表、详情、公开评论浏览
- 题库：题库目录、题库详情、练习入口说明
- 公开方向信息：就业招聘会/岗位详情，考研院校与资料，考公岗位/分数线/考试日历，留学院校项目/案例/经验

### 4.2 学生方向层

由后端用户方向决定进入：

- `kaoyan`
- `kaogong`
- `job`
- `liuxue`

前端需显式维护映射：

- `liuxue -> /studyabroad`

### 4.3 管理层

管理员只接后端真实存在的治理和运营接口：

- 内容审核与举报
- 用户治理
- 就业运营
- 考研/考公数据治理
- 题库治理

不伪造留学独立后台。

## 5. 全站结构模型

本次 `frontendv1` 采用五层体验模型：

1. 入口层
2. 角色层
3. 方向层
4. 工作面层
5. 深操作层

### 5.1 入口层

`/` 与 `/login`

- `/` 是游客门厅，不是传统首页
- `/login` 不是一张表单页，而是身份选择与进入路径控制页

### 5.2 角色层

用户登录后进入三类壳：

- 游客壳
- 学生壳
- 管理员壳

### 5.3 方向层

仅学生壳内部存在：

- 就业站
- 考研站
- 考公站
- 留学站

### 5.4 工作面层

每个方向站只展示 2 到 4 个主工作面入口，不直接展示全部功能。

### 5.5 深操作层

列表、详情、编辑、结果页继续下钻，每页只负责一个动作。

## 6. 角色主站与控件分配

这一节是本设计最关键的部分：同样是“功能入口”，但会根据后端能力更换控件类型，而不是继续统一用卡片。

### 6.1 游客主站：导览厅

目标：让游客先逛内容，再决定是否进入身份语境。

页面构成：

- 左侧：方向目录脊线
- 中央：公共内容导览
- 右侧：登录后解锁面板

控件分配：

- 社区：`刊物目录 + 热帖纵列`
- 题库：`科目树 + 练习说明条`
- 公开方向入口：`索引清单`
- 受限动作：`醒目提示条`

不使用：

- 大面积营销 hero
- 四方向等宽大卡片
- 一屏塞完所有公共功能

游客主站线框：

```text
┌──────────┬──────────────────────────────┬──────────────┐
│ 阶段脊线 │ 今日可浏览内容                │ 登录后解锁    │
│ 社区     │ 社区目录 / 热门讨论           │ 发帖          │
│ 题库     │ 题库目录 / 公开题库           │ 收藏          │
│ 方向入口 │ 招聘会 / 院校 / 日历 / 案例   │ 练习会话      │
└──────────┴──────────────────────────────┴──────────────┘
```

### 6.2 社区：阅读站，而不是论坛大厅

后端结构决定社区更适合内容型界面，而不是社交媒体流。

页面器具：

- 社区列表：`目录筛选条 + 文章列表`
- 帖子详情：`正文纸面 + 评论账本 + 附件抽屉`
- 发帖页：`编辑桌`

关键提示：

- 游客浏览时顶部固定显示“当前处于公共浏览层”
- 点赞、评论、收藏、发帖按钮在游客态统一弹出“登录后继续”

### 6.3 题库：训练目录，不是练习大拼盘

基于 `QuestionBankController` 与 `PracticeController`，题库应拆成三类器具：

- 目录器具：`题库树`
- 过程器具：`练习会话卡`
- 结果器具：`成绩图谱 / 错题账本 / 历史时间轴`

页面分层：

- 题库首页：题库树与筛选抽屉
- 题库详情：题库说明、题型摘要、开始练习按钮
- 练习会话页：单题工作面
- 提交结果页：成绩摘要与错题去向
- 错题页：错题账本
- 统计页：时间粒度切换图谱

关键提示：

- 游客可浏览目录，但开始练习必须弹登录选择框
- 练习过程必须显式提示“答案已暂存”“交卷完成”“返回题库详情”

### 6.4 就业站：求职作战桌

后端就业模块非常完整，因此不应继续做成普通入口卡。

主站器具：

- 左：`求职阶段脊线`
- 中：`今日作战桌`
- 右：`通知收件箱`

三个主工作面：

- 简历卷宗
- 岗位筛选台
- 投递跟踪轨道

控件分配：

- 简历：`卷宗编辑器 + 附件盒`
- 推荐：`岗位比对表 + 匹配理由侧栏`
- 招聘会：`日程板`
- 投递：`pipeline 轨道`
- 通知：`收件箱`

线框：

```text
┌──────────┬──────────────────────────────┬──────────────┐
│ 建档     │ 今日作战桌                    │ 提醒收件箱    │
│ 筛岗     │ 简历状态 / 推荐摘要 / 待跟进  │ 未读通知      │
│ 跟踪     │ 进入一个主动作                │ 已读归档      │
└──────────┴──────────────────────────────┴──────────────┘
```

### 6.5 考研站：复习台账

考研后端核心不是营销展示，而是计划、资料、比较与陪伴。

主站器具：

- 学校对照板
- 分数线抽屉
- 学习计划日历
- 打卡热力图
- 资料柜

不再使用统一模块卡，而是让不同数据结构用不同容器：

- 学校与分数线：`对照板 + 抽屉`
- 学习计划：`日历台账`
- 打卡：`热力图`
- 资料：`资料柜`
- 咨询与自习室：`预约条 / 房间清单`

### 6.6 考公站：报考雷达室

考公功能更像判断与节奏管理，而不是纯内容消费。

主站器具：

- 岗位匹配矩阵
- 分数线账本
- 考试日历墙
- 模拟面试房间卡

器具分配：

- 岗位列表：`筛选矩阵`
- 分数线：`年度账本`
- 日历：`轨道式日历墙`
- 匹配历史：`记录抽屉`
- 面试：`房间卡 + 材料附件条`

### 6.7 留学站：申请航线图

留学后端最强的是申请、时间线、案例、经验与资料。

主站器具：

- 项目目录
- 申请航线图
- 时间线轨道
- 材料箱
- 案例卷宗

器具分配：

- 学校项目：`项目目录册`
- 录取案例：`卷宗卡`
- 经验：`摘录册`
- 申请：`航线图`
- 时间线：`轨道`
- 材料：`材料箱 + 附件清单`

### 6.8 管理员主站：治理队列室

管理员首页必须彻底摆脱学生式主站。

布局：

- 左：优先级队列
- 中：工单列表
- 右：处置摘要与快捷操作

首页入口不再是四张治理卡，而是四条队列：

- 待审核内容
- 举报与评论举报
- 异常用户
- 运营任务

进入具体模块后再展开器具：

- 审核：`工单队列`
- 举报：`处置单`
- 用户管理：`用户账册`
- 就业运营：`数据台账 + 触发台`
- 题库治理：`目录管理器`

管理员主站线框：

```text
┌─────────────┬────────────────────────────┬──────────────┐
│ 优先级队列   │ 今日待处理工单              │ 处置面板      │
│ 审核 19      │ 审核列表 / 举报列表 / 用户  │ 通过 / 拒绝   │
│ 举报 7       │ 只显示当前队列对象          │ 标记完成      │
│ 异常用户 14  │                            │ 返回总台      │
└─────────────┴────────────────────────────┴──────────────┘
```

## 7. 页面路径与返回设计

所有功能都必须逐层深入，因此返回路径不能靠浏览器后退。

### 7.1 固定返回结构

每个深页顶部都有三段式返回结构：

- 所属站点
- 来源列表或来源工作面
- 当前动作

例如：

- 游客门厅 / 社区 / 帖子详情
- 就业站 / 推荐结果 / 岗位详情
- 管理总台 / 举报队列 / 举报详情

### 7.2 返回控件层级

- 一级返回：回工作站或总台
- 二级返回：回列表
- 三级返回：放弃当前编辑

### 7.3 成功后的回流规则

- 创建类动作：回来源列表，并高亮新项
- 编辑类动作：回详情页或列表页，并显示成功条
- 练习提交：回结果页，不直接回目录
- 登录完成：进入对应主站，不回游客深操作页
- 退出登录：回游客门厅

## 8. 预览态与虚拟数据规则

鉴于当前前后端联动并不完整，本轮前端重设计需要继续支持“按后端数据结构模拟有数据时的样子”，但必须明确提示是预览。

### 8.1 模拟原则

- 只模拟后端真实会返回的字段结构
- 不虚构不存在的后端流程
- 预览态文案要明显，不伪装成线上真实数据

### 8.2 预览提示位置

以下位置必须常驻提示：

- 登录身份选择后进入的方向站顶部
- 管理员总台顶部
- 所有使用虚拟数据的工作面右上角

提示语统一为：

- `当前为结构预览：页面使用后端字段对应的虚拟数据展示最终布局。`

### 8.3 游客与身份切换

登录交互保持本轮已有机制：

- 点击登录时弹出身份选择
- 选择 `考研 / 考公 / 就业 / 留学 / 管理员`
- 退出时回到游客态

## 9. 文案与提示规范

为了避免 AI 味和过度营销，文案采用“说明动作与边界”的方式，不做空泛口号。

### 9.1 文案原则

- 用动作命名，不用抽象愿景命名
- 先说能做什么，再说限制什么
- 错误、空态、权限不足都给下一步

### 9.2 典型提示

- `登录后继续发帖`
- `当前仅浏览公开内容`
- `平台不会自动投递，请前往岗位原链接完成申请`
- `附件仅保存与下载，不参与自动解析`
- `你正在查看治理预览，处置结果不会写回后端`

## 10. 数据状态与异常处理

### 10.1 必须覆盖的状态

- 加载中
- 空数据
- 权限不足
- 请求超时
- 预览态数据
- 真实数据加载成功

### 10.2 状态呈现规则

- 加载中：不使用通用骨架屏大块占位，改用结构化线框占位
- 空数据：提示下一步动作
- 权限不足：明确告诉用户回哪里
- 超时：给重试和回上层

示例：

- 题库空态：`当前方向还没有题库，先返回目录切换科目。`
- 社区权限态：`游客不能评论。登录后继续，或返回社区列表继续浏览。`
- 管理员空队列：`当前队列已清空，返回总台查看下一组工单。`

## 11. 响应式与可访问性

### 11.1 移动端策略

桌面端强调三栏，移动端改成：

- 阶段脊线折叠为顶部步骤条
- 右侧抽屉改为底部抽屉
- 中央工作面保持单列

### 11.2 可访问性

- 所有返回路径可键盘到达
- 颜色不作为唯一状态区分
- 预览提示、权限提示、站外跳转提示必须可读
- 尊重 reduced motion

## 12. 测试与验收标准

### 12.1 设计验收

如果实现后仍满足以下任一现象，则判定设计失败：

- 看起来仍像旧 `frontend` 的首页换皮
- 多个方向主站仅标题不同、结构相同
- 功能仍主要通过卡片栅格平铺
- 用户无法一眼看出当前所在层级

### 12.2 功能验收

实现后需要重点验证：

- 游客进入社区、题库、公开方向内容的路径
- 登录弹窗选择身份进入对应主站
- 退出回游客门厅
- 各方向主站的器具差异明显
- 关键深页的返回路径正确
- 预览态提示持续可见

### 12.3 优先实现顺序

1. 登录页与游客门厅重构
2. 社区改成阅读站
3. 题库改成训练目录
4. 就业站改成求职作战桌
5. 管理员首页改成治理队列室
6. 再扩展考研、考公、留学主站

## 13. 实施约束

- 不修改后端接口与字段结构
- 保留现有身份弹窗进入机制
- 允许在 `frontendv1` 中使用虚拟数据模拟真实布局
- 后续实现必须避免继续回到“hero + 卡片栅格”的骨架

## 14. 结论

本次重设计的关键不是“做得更花”，而是让前端终于和后端功能性质对上号。

社区应该像阅读站，题库应该像训练目录，就业应该像作战桌，考研应该像复习台账，考公应该像报考雷达室，留学应该像申请航线图，管理员应该像治理队列室。只有这样，用户才不会再觉得它只是旧 `frontend` 的另一层皮。
