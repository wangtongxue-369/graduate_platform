# 考研择校账本重构设计

日期：2026-06-14

## 1. 背景

当前 `frontendv2` 中的考研“择校账本”已经接上了旧版考研分数线相关后端接口，但与旧 `frontend` 的 `ScoreQueryPage` 相比还有两类明显差距：

1. 查询能力不足
   `frontendv2` 当前只保留了 `region`、`majorCategory`、`year`、`is985`、`keyword` 等少量条件，未覆盖旧版已有的：
   `schoolName`、`region`、`majorCategory`、`majorName`、`year`、`is985`、`is211`、`isDoubleFirstClass`

2. 结果列表信息密度不足
   当前结果区更偏“摘要账本行”，不像旧版那样是清晰可扫的查询列表，用户无法快速横向对比：
   `院校 / 专业 / 年份 / 总分线 / 单科线 / 招生人数 / 报录比 / 收藏`

用户已经明确要求：

- 以旧 `frontend + 后端` 的功能路线为准
- 新版不要直接照搬旧页面布局与皮肤
- 结果区优先恢复“真正的查询列表感”
- 右侧保留筛选栏
- 对比保留“勾选后弹窗对比”
- 收藏保留主表就地收藏，并继续保留独立收藏页

## 2. 目标

本次重构只针对 `frontendv2` 的考研择校模块，不改后端接口。

目标：

1. 补回旧版 `ScoreQueryPage` 的核心查询能力
2. 让结果区回到“高可扫读”的查询表格体验
3. 保留 `frontendv2` 的页面分层方式：
   主区看结果，右栏管筛选，弹窗做对比，独立页看收藏
4. 不回退成旧版整体视觉复刻

非目标：

1. 不改后端接口结构
2. 不新增后端筛选能力之外的假筛选
3. 不将收藏页并回主页面
4. 不把对比功能改成右栏固定区或页内常驻区

## 3. 旧新版映射

旧版入口：

- 路由：`/kaoyan/scores`
- 页面：`frontend/src/pages/kaoyan/ScoreQueryPage.jsx`

新版入口：

- 主账本：`/station/kaoyan/schools`
- 收藏页：`/station/kaoyan/schools/favorites`

功能映射关系：

- 旧版“分数线/报录比查询” -> 新版“择校账本主页”
- 旧版“收藏分数线” -> 新版“主页就地收藏 + 独立收藏页”
- 旧版“勾选后弹窗对比” -> 新版“继续保留勾选后弹窗对比”

## 4. 页面结构

页面采用三段结构：

### 4.1 主区

主区负责展示结果，不承载大段筛选表单。

主区包含：

1. 页面引导区
   - 标题：强调这是“择校账本 / 查询账本”
   - 面包屑：`考研主站 / 择校账本`
   - 次动作：`查看收藏账本`

2. 结果状态条
   - 当前命中结果数
   - 当前筛选摘要
   - 当前已勾选对比数量

3. 查询结果主表
   - 使用真正的表格式布局
   - 保留横向字段对齐能力
   - 支持展开次信息

### 4.2 右侧筛选栏

右栏固定为筛选控制区，不在主区顶部重复铺开筛选项。

右栏负责：

1. 关键词检索
2. 基础筛选
3. 院校标签筛选
4. 应用 / 清空操作

### 4.3 对比弹窗

仍由主区勾选结果触发，不改成交互侧栏。

## 5. 查询筛选设计

## 5.1 补回的筛选项

新版主页需要覆盖旧版已有筛选能力：

- 院校名称 `schoolName`
- 地区 `region`
- 专业门类 `majorCategory`
- 具体专业 `majorName`
- 年份 `year`
- 985 `is985`
- 211 `is211`
- 双一流 `isDoubleFirstClass`

## 5.2 右栏控件类型

为避免直接复刻旧版顶栏大表单，右栏使用更紧凑的控件组织：

- `院校名称`：文本输入
- `地区`：下拉选择
- `专业门类`：下拉选择
- `具体专业`：文本输入
- `年份`：下拉选择
- `985`：三态切换 `不限 / 是 / 否`
- `211`：三态切换 `不限 / 是 / 否`
- `双一流`：三态切换 `不限 / 是 / 否`

## 5.3 右栏分组

右栏分为三组：

1. 关键词检索
   - 院校名称
   - 具体专业

2. 基础筛选
   - 地区
   - 专业门类
   - 年份

3. 院校标签
   - 985
   - 211
   - 双一流

底部固定两个动作：

- `应用筛选`
- `清空条件`

## 5.4 筛选触发规则

- 右栏输入与切换先只更新本地草稿条件，不在每次键入时立即请求后端
- 用户点击 `应用筛选` 后，才用当前条件刷新主表结果
- 用户点击 `清空条件` 后，恢复默认条件，并重新加载默认结果
- 对比与展开状态不跟随输入中的草稿条件即时重置，只在真正应用新筛选后再按需清理

## 6. 查询结果主表设计

## 6.1 结果区原则

结果区优先级明确如下：

1. 第一目标：像旧版查询表，而不是摘要卡片
2. 第二目标：数值字段横向对齐，便于快速扫读
3. 第三目标：次信息通过展开行承接，而不是把主表做成超宽长表

## 6.2 主表固定列

主表默认展示这些列：

1. 勾选对比
2. 院校
3. 专业
4. 年份
5. 总分线
6. 政治
7. 外语
8. 业务课 1
9. 业务课 2
10. 计划招生
11. 报录比
12. 操作
13. 展开

说明：

- `院校` 列中可补充最小必要的二级信息，如 `985/211` 标签，但不在此列堆太多说明文字
- `专业` 只保留足够识别的信息，不将备注和来源混入主列
- `操作` 列保留旧版用户最常用动作

## 6.3 主表操作列

主表操作列保留：

- `收藏分数线 / 取消收藏`

勾选对比保留在表格最左侧，延续旧版使用习惯。

## 6.4 主表分页

- 主表底部保留分页控件，恢复旧版“查询列表 + 分页”的使用节奏
- 默认页大小按旧版查询体验对齐为 `10`
- 分页对象是最终可比较的分数线结果，而不是院校基础档案数
- 摘要区可同时展示 `院校档案命中数` 与 `分数线结果数`，但翻页只作用于主表结果

## 7. 展开行设计

## 7.1 展开行目标

展开行用于承接主表里不适合全部横向展示的次信息，避免主表过宽，同时保住旧版重要字段。

## 7.2 展开行字段

展开后展示：

- 地区 / 省份
- 985 / 211 / 双一流
- 国家线 / 院线
- 实际报考人数
- 备注 `note`
- 来源 `source`

## 7.3 展现规则

- 默认折叠
- 单行独立展开，不影响其他行结果阅读
- 如果字段为空，则该字段不展示占位内容
- 展开区视觉上更像“表格附页”，而不是另一张独立卡片
- 主表只展示真正可比较的分数线记录，不再生成“等待分数线数据”的院校占位行

## 8. 收藏页设计

保留现有独立收藏页：

- 路由：`/station/kaoyan/schools/favorites`

收藏页不再承载全量筛选，只展示已收藏记录。

收藏页信息结构需要与主表的核心识别信息保持一致，至少显示：

- 院校
- 专业
- 年份
- 总分线
- 报录比（若有）
- 计划招生（若有）

如果后端返回更多信息，可在收藏页继续复用展开行或简化明细区，但收藏页不承担完整查询职责。

## 9. 对比弹窗设计

## 9.1 交互保持不变

保留旧版交互：

- 用户勾选多条记录
- 至少勾选 `2` 条后才能打开弹窗

不改为：

- 右栏常驻对比
- 主区嵌入对比
- 抽屉式对比

## 9.2 对比字段

弹窗内需尽量对齐旧版对比字段：

- 院校
- 专业
- 年份
- 总分线
- 政治线
- 外语线
- 业务课 1
- 业务课 2
- 计划招生
- 报考人数
- 报录比
- 国家线 / 院线

## 9.3 限制

- 最多对比 5 条
- 弹窗内保留 `移除对比项`

## 10. 数据与状态设计

## 10.1 数据来源

继续复用现有后端接口：

- `kaoyanApi.schoolsPage(...)`
- `kaoyanApi.scoreLinesPage(...)`
- `kaoyanApi.favoriteScoreLines(token)`
- `kaoyanApi.favoriteScoreLine(id, token)`
- `kaoyanApi.unfavoriteScoreLine(id, token)`

接口能力需要在规格中写清楚：

- `schoolsPage` 当前真实支持的院校侧条件以 `backend` 为准：`name / region / province / is985 / is211 / isDoubleFirstClass / schoolType`
- `scoreLinesPage` 当前真实支持的分数线侧条件以 `backend` 为准：`schoolId / schoolName / year / majorCategory / majorName`
- 因此本轮不会假定存在单个后端接口可一次性完成全部复合筛选，而是由前端在已有接口之上完成拼装与裁切

## 10.2 主页状态

主页至少需要维护：

- `draftFilters`
- `appliedFilters`
- `rows`
- `meta`
- `loading`
- `notice`
- `favoriteIds` 或等价状态
- `compareIds`
- `compareModalOpen`
- `expandedRowIds` 或单行展开状态
- `page`
- `pageSize`

## 10.3 结果拼装

若后端仍保持“院校列表 + 分数线列表”分开返回，则前端继续在 `kaoyanPageData.js` 中进行拼装，但拼装结果需要满足新表格结构：

- 核心列字段直接可渲染
- 次信息字段可直接用于展开区
- 对比弹窗字段完整可取

具体拼装与筛选策略明确如下：

1. 院校侧筛选条件走 `schoolsPage`
   - `schoolName` 需要映射到院校接口真实参数 `name`
   - `region / is985 / is211 / isDoubleFirstClass` 也在院校接口侧生效

2. 分数线侧筛选条件走 `scoreLinesPage`
   - `schoolName / majorCategory / majorName / year`

3. 前端按 `schoolId` 将两路结果合并为单行账本记录

4. 当用户使用院校侧筛选时，前端以院校结果集的 `schoolId` 作为白名单，对分数线结果做二次裁切

5. 主表分页针对“合并并裁切后的分数线结果”在前端执行，避免把院校档案分页误当成主表分页

6. 若院校接口与分数线接口命中情况不一致，主表以“是否有可比较分数线记录”为准，摘要区再补充说明命中差异

## 11. 异常与降级

1. 未登录
   - 可以公开查询
   - 收藏与对比中的登录依赖动作给出明确提示

2. 查询失败
   - 保留现有 `notice` 反馈机制
   - 主区显示“查询失败 / 使用预览数据 / 请检查后端”一类清晰提示

3. 字段缺失
   - 主表缺字段时用 `-`
   - 展开区缺字段时直接收起对应项
   - 不显示“未知未知未知”的空壳内容

4. 结果为空
   - 明确提示“当前筛选下没有可比较的分数线结果”
   - 保留清空筛选入口
   - 若存在院校档案命中但无分数线记录，可在空状态补充说明“已命中院校档案，但暂无可比较分数线数据”

## 12. 实现边界

本轮实现预计只改前端，不动后端。

优先修改范围：

- `frontendv2/src/pages/student/kaoyan/KaoyanSchoolsPage.jsx`
- `frontendv2/src/pages/student/kaoyan/KaoyanSchoolFavoritesPage.jsx`
- `frontendv2/src/pages/student/kaoyan/kaoyanPageData.js`
- 可能新增局部展示组件，如：
  - 查询结果表
  - 展开行
  - 对比弹窗

不计划修改：

- 后端 controller / service
- 收藏接口
- 分数线查询接口协议

## 13. 测试要求

需要补充或更新的前端测试至少包含：

1. 路由仍可访问：
   - `/station/kaoyan/schools`
   - `/station/kaoyan/schools/favorites`

2. 主表核心列渲染正确

3. 右栏筛选项完整渲染

4. 勾选对比后可打开弹窗

5. 对比弹窗包含旧版关键字段

6. 展开行可展开 / 收起并显示次信息

7. 收藏动作仍可触发原有接口

8. 收藏页仍能正确加载已收藏记录

## 14. 推荐实施顺序

1. 先重构主页筛选状态与右栏控件
2. 再把结果区改成主表 + 展开行
3. 再补回对比弹窗字段
4. 最后调整收藏页信息结构与回归测试

## 15. 设计结论

本次“择校账本”重构采用以下最终方案：

- 结果区回归真正的查询表格感
- 采用 `主表 + 次信息展开行`
- 右侧保留筛选栏
- 查询能力对齐旧版 `ScoreQueryPage`
- 收藏保留主表就地操作 + 独立收藏页
- 对比保留旧版弹窗交互，并补回旧版对比字段

这是一版“功能路线向旧版看齐、页面组织向新版靠拢”的折中方案。
