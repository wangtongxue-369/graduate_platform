# 管理后台就业管理页工具台化改版设计
日期：2026-06-02

主题：`/admin/employment` 从“双系统并列”改为“单对象工具台”

## 1. 背景

当前“招聘会与岗位管理”页面把两套完整管理系统同时放在同一屏：

- 招聘会表单
- 岗位表单
- 招聘会列表
- 岗位列表

虽然这让信息“都在一页”，但实际会带来三个问题：

- 页面主任务不明确。用户很难在首屏快速判断自己当前是在管理招聘会还是管理岗位。
- 两套编辑工作流并列堆叠，页面视觉重心分散，列表区和表单区互相抢注意力。
- 为了维持同屏布局而做的“强制对齐”会在中等宽度下变得别扭，列表卡片和表单区域都容易显得拥挤。

问题本质不是某个卡片样式不统一，而是页面信息架构本身缺少主次。

## 2. 目标

把当前页面整理为一个更符合后台录入与维护心智的“工具台型”页面：

- 用户先选择要管理的对象：`招聘会` 或 `岗位`
- 页面一次只服务一类对象
- 当前对象的“表单编辑”和“列表浏览”放在同一工作区内
- 仍保留整页级统计、全局提示、主题切换兼容和现有业务接口

## 3. 设计结论

采用 `方案 A：单对象工具台 + 管理对象 Tab`。

页面结构调整为：

1. 顶部总览区
2. 管理对象切换区
3. 当前对象工作区

不再同时展示两套完整系统。

## 4. 页面结构

### 4.1 顶部总览区

保留当前页面已有的：

- 返回后台入口
- 页面标题与说明
- 整页统计卡
- 错误 / 成功消息提示

这部分属于全页总览，不跟随 Tab 切换。

### 4.2 管理对象切换区

在总览区下方新增 `管理对象 Tab`：

- `招聘会管理`
- `岗位管理`

职责：

- 作为当前工作上下文的唯一切换入口
- 明确告诉管理员“我现在正在管理哪一类数据”
- 决定下方工作区的表单、列表、空状态和局部说明

Tab 使用现有后台主题语义样式，不新增独立主题状态。

### 4.3 当前对象工作区

Tab 下只渲染当前对象的一套工作区：

- 左侧：当前对象表单
- 右侧：当前对象列表

即：

- 选中 `招聘会管理` 时，只显示招聘会表单 + 招聘会列表
- 选中 `岗位管理` 时，只显示岗位表单 + 岗位列表

这样用户在认知上始终只处理一类对象，不再受到另一类系统干扰。

## 5. 交互设计

### 5.1 表单状态

- 招聘会表单和岗位表单状态继续独立维护
- 切换 Tab 时，不强制清空另一类对象的草稿或编辑态
- 当前 Tab 内继续沿用现有“新增 / 编辑 / 取消编辑”流程

### 5.2 列表操作

每个列表项继续保留现有操作：

- 编辑
- 触发提醒
- 删除

但这些操作只出现在当前对象列表中，不再与另一类数据并列出现。

### 5.3 局部说明

每个 Tab 需要有自己的局部说明与数量反馈，例如：

- 当前对象总数
- 当前启用数
- 空状态文案
- 当前工作区用途说明

这些说明应服务于当前对象，不再用整页统一文案替代。

## 6. 布局规则

### 6.1 桌面端

当前对象工作区采用主从式布局：

- 表单列固定在约 `420px - 460px`
- 列表列占据剩余宽度

原因：

- 表单更适合稳定宽度，减少字段跳动
- 列表更适合占据更多横向空间以容纳卡片、元信息和操作区

避免再使用两个完全等宽的大面板。

### 6.2 中等宽度

当宽度不足以舒适容纳“表单列 + 列表列”时：

- 工作区改为上下堆叠
- 优先保证表单字段可读性和列表卡片舒展度

不再为了保留双栏而强行压缩。

### 6.3 移动端

- Tab 纵向可点击面积充足
- 表单与列表完全上下堆叠
- 卡片操作按钮允许换行或全宽排列
- 不出现横向滚动

## 7. 样式与主题约束

本次改版必须继续遵守现有后台主题统一规则：

- 主题来源仍然是 `PreferencesContext -> document.documentElement.dataset.theme -> CSS 变量`
- 不新增后台专属 React 主题状态
- 不对浅色 / 深色做页面内条件渲染分支
- 新样式继续基于现有后台语义容器扩展

允许新增的类应聚焦于：

- 管理对象 Tab
- 单对象工作区容器
- 表单列 / 列表列布局
- 当前对象局部工具头部

## 8. 实现边界

本次改版包含：

- `frontend/src/pages/admin/EmploymentManagementPage.jsx`
- `frontend/src/App.css`
- `frontend/src/App.adminTheme.test.js`

本次改版不包含：

- 后端接口变更
- 招聘会 / 岗位数据结构调整
- 新的批量操作流程
- 权限模型调整
- 全站后台布局总重构

## 9. 测试与验证

至少覆盖以下验证点：

### 9.1 静态回归

在 `App.adminTheme.test.js` 中增加或调整断言，确保：

- 页面存在管理对象 Tab 结构
- 页面不再使用“双对象同屏并列”的旧结构约束
- 页面存在当前对象专属工作区容器
- 页面继续复用后台共享主题语义类

### 9.2 构建验证

运行：

- `npm test -- src/App.adminTheme.test.js`
- `npm run build`

### 9.3 视觉验收

重点检查：

- 默认进入页时主任务是否明确
- Tab 切换后工作区是否只服务当前对象
- 中等宽度下是否比旧版更自然
- 小屏下是否无横向滚动
- 浅色 / 深色主题下层级是否都稳定

## 10. 成功标准

若满足以下条件，即视为本次设计成功：

- 页面首屏能明确表达“先选对象，再管理该对象”
- 招聘会与岗位不再作为两套完整系统同屏竞争注意力
- 桌面端不再依赖强制等宽对齐维持秩序
- 中等宽度和移动端布局更自然
- 不破坏现有主题切换、表单逻辑和列表操作逻辑
