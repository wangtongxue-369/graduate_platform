# 全局控制面板设计

日期：2026-06-01
主题：全站主题、字体大小、语言模式控制面板

## 1. 目标

为前端站点增加一个全局可访问的悬浮控件。用户点击后打开控制面板，可对以下偏好进行全站控制：

- 主题模式：浅色、深色、跟随系统
- 字体大小：通过滑块连续调节
- 语言模式：简体中文、双语提示、English（首期为占位模式）

首期目标是建立统一的全局偏好基础设施，让设置能够跨页面生效并持久化，为后续更多个性化选项留出扩展位。

## 2. 设计原则

- 尽量少改业务页面：通过全局上下文和根节点属性控制样式，不逐页重写逻辑。
- 先搭框架，后扩展文案：语言模式首期只建立站点级模式和切换入口，不在这一轮翻译整个站点。
- 兼容现有视觉系统：复用现有 CSS 变量体系，避免引入新的样式框架。
- 移动端可用：悬浮入口和面板需要在窄屏下正常操作。
- 设置可持久化：刷新页面后保留用户偏好。

## 3. 方案对比

### 方案 A：全局 PreferencesContext + 悬浮控制面板

做法：

- 新增 `PreferencesContext`
- 在 `main.jsx` 根部包裹 `PreferencesProvider`
- Provider 负责读取、保存、同步 DOM 属性和 CSS 变量
- `App` 中常驻渲染悬浮按钮和控制面板

优点：

- 状态集中，后续可继续扩展更多设置
- 页面改动少
- 测试和排查更清晰

缺点：

- 需要补一个新的全局上下文和样式接入层

### 方案 B：面板组件内部管理状态，直接操作 DOM

做法：

- 只加一个浮层组件
- 组件自己读取 `localStorage` 并直接写 `document.documentElement`

优点：

- 实现速度快

缺点：

- 状态来源分散
- 后续如果页面里也要读取偏好会变得别扭

### 方案 C：把设置入口收进 Navbar

做法：

- 在顶部导航增加设置菜单

优点：

- 视觉上更统一

缺点：

- 并非所有页面都适合依赖顶部导航入口
- 移动端使用成本更高
- 与“全局悬浮控件”目标不完全一致

推荐采用方案 A。

## 4. 范围

本次实现包含：

- 全局偏好状态管理
- 悬浮按钮与控制面板 UI
- 浅色、深色、跟随系统三种主题切换
- 根字号缩放
- 语言模式切换和基础对外接口
- 本地持久化

本次不包含：

- 全站完整国际化改造
- 服务端存储用户偏好
- 额外主题色定制
- 无障碍朗读、对比度增强等高级辅助能力

## 5. 信息架构

新增模块建议如下：

- `frontend/src/context/PreferencesContext.jsx`
  - 管理偏好状态
  - 向 DOM 同步 `data-theme`、`data-language-mode`
  - 同步字体缩放 CSS 变量
- `frontend/src/components/PreferencesPanel.jsx`
  - 悬浮按钮
  - 控制面板
  - 面板开关、点击外部关闭、Esc 关闭
- `frontend/src/lib/preferences.js`
  - 偏好默认值、枚举、存储 key、规范化函数

接入点：

- `frontend/src/main.jsx`
  - 挂载 `PreferencesProvider`
- `frontend/src/App.jsx`
  - 常驻渲染 `PreferencesPanel`
- `frontend/src/index.css`
  - 根变量、深浅主题变量、字体缩放变量
- `frontend/src/App.css`
  - 面板与按钮样式

## 6. 数据模型

偏好对象：

```js
{
  theme: 'system' | 'light' | 'dark',
  fontScale: number,
  languageMode: 'zh-CN' | 'bilingual' | 'en'
}
```

存储 key：

```js
'gp_preferences'
```

默认值：

```js
{
  theme: 'system',
  fontScale: 1,
  languageMode: 'zh-CN'
}
```

规范化要求：

- 读取本地数据时若 JSON 解析失败，回退到默认值
- 若 `fontScale` 不是数字或超出允许范围，回退默认值
- 若枚举字段值不在允许集合内，单字段回退默认值

## 7. 状态流

初始化：

1. Provider 读取 `localStorage`
2. 合并默认值并规范化
3. 监听系统主题变化，仅在 `theme === 'system'` 时生效
4. 将实际主题和值同步到 `document.documentElement`

更新：

1. 面板触发 `setTheme` / `setFontScale` / `setLanguageMode`
2. Provider 更新 React 状态
3. Provider 将结果写回 `localStorage`
4. Provider 同步 DOM 属性和 CSS 变量

消费：

- 样式系统通过 `:root`、`[data-theme="dark"]` 和 CSS 变量消费
- 需要读取语言模式或其他偏好的组件可通过 `usePreferences()` 获取

## 8. 主题实现

### 8.1 DOM 挂载

在 `document.documentElement` 上挂：

- `data-theme="light"` 或 `data-theme="dark"`
- `data-language-mode="zh-CN" | "bilingual" | "en"`

其中：

- 当用户选择 `system` 时，不直接保留 `system` 作为最终 DOM 主题值，而是根据 `matchMedia('(prefers-color-scheme: dark)')` 解析为 `light` 或 `dark`
- React 状态中仍保留原始用户选择 `system`

### 8.2 CSS 变量

当前项目已经广泛使用：

- `--ink`
- `--muted`
- `--primary`
- `--primary-ink`
- `--accent`
- `--line`
- `--surface`
- `--shadow`

本次补充：

- `--bg`
- `--text`
- `--ink-muted`
- `--panel-surface`
- `--panel-border`
- `--panel-shadow`
- `--font-scale`

处理方式：

- 在 `:root` 下定义浅色默认值
- 在 `[data-theme="dark"]` 下覆写关键变量
- `body`、`.app`、`.nav`、卡片、面板优先依赖变量而不是写死浅色背景

### 8.3 暗色主题覆盖策略

优先覆盖这些全局基础区域：

- `body`
- `.app`
- `.nav`
- `.feature-card`
- `.panel-card`
- `.modal-card`
- `.timeline-item`
- `.comment`
- `.file-card`
- 控件输入框、按钮 hover 面

目标不是逐像素重新设计，而是先把“整体可用、对比清晰、主要容器统一”做好。

## 9. 字体大小实现

采用根字号缩放，并通过滑块连续控制，不逐组件写分支。

建议范围：

- 最小值：`0.875`
- 默认值：`1`
- 最大值：`1.25`
- 步进：`0.025`

对应根字号大致范围：

- `0.875` -> `14px`
- `1` -> `16px`
- `1.25` -> `20px`

实现方式：

- `:root { font-size: calc(16px * var(--font-scale)); }`
- Provider 将 `fontScale` 直接同步为 CSS 变量值
- 面板内使用 `input[type="range"]` 控制该值

这样多数使用 `rem`、`clamp`、继承字体的区域会自然缩放。对于项目里已经写死的部分 `px` 字号，首期允许它们暂时保持不变，不作为阻断项。

滑块 UI 要求：

- 显示当前倍率，例如 `100%`
- 提供最小、默认、最大三个视觉刻度说明
- 可通过“恢复默认”回到 `1`

## 10. 语言模式实现

### 10.1 首期行为

首期不做全站完整翻译，而是完成下面三件事：

- 提供语言模式设置入口
- 将模式存入全局状态
- 暴露 `usePreferences()` 供后续页面逐步接入文案切换

### 10.2 模式含义

- `zh-CN`
  - 保持现状，以中文为主
- `bilingual`
  - 用于后续页面逐步补充“中文 + 英文辅助标签”
- `en`
  - 当前仍以中文页面为主，但全局模式已建立，作为后续国际化预留

### 10.3 首期 UI 表达

为了避免误导，面板中对 `en` 和 `bilingual` 需要附带简短说明，例如：

- `双语提示`：逐步覆盖关键导航与说明文案
- `English`：国际化框架预留，当前页面内容仍以中文为主

## 11. 控制面板 UI

### 11.1 入口

- 固定在右下角
- 桌面端距离边缘 20px 到 28px
- 移动端适当缩小
- 使用圆角较大的悬浮按钮，视觉上与站点现有卡片风格一致

### 11.2 面板内容

结构：

- 面板标题和简短说明
- 主题分组
- 字体大小滑块分组
- 语言模式分组
- “恢复默认”按钮

交互：

- 点击按钮展开/收起
- 点击遮罩或面板外关闭
- `Esc` 关闭
- 当前选项有明显选中态

### 11.3 可访问性

- 入口按钮带 `aria-label`
- 面板使用 `role="dialog"`
- 面板标题通过 `aria-labelledby` 关联
- 键盘可操作

## 12. 与现有代码的集成方式

### 12.1 `main.jsx`

现状：

- 已有 `AuthProvider`

改造：

- 在 `AuthProvider` 外层或内层增加 `PreferencesProvider`

建议：

- `BrowserRouter` -> `PreferencesProvider` -> `AuthProvider` -> `App`

原因：

- 偏好不依赖认证
- 全应用包括登录页都能使用

### 12.2 `App.jsx`

现状：

- 根组件中常驻 `DevBar`

改造：

- 保留 `DevBar`
- 新增常驻 `PreferencesPanel`

### 12.3 `index.css`

改造重点：

- 把 `background`、`color` 更明确地绑定到全局变量
- 新增暗色模式变量
- 新增字体缩放变量
- 为原生表单和滚动条适配深浅色的基础色

### 12.4 `App.css`

改造重点：

- 把 `.app`、`.nav` 等明显写死浅色背景的地方改为变量驱动
- 新增控制面板样式
- 处理移动端断点和层级

## 13. 错误处理

- `localStorage` 读取失败：静默回退默认值
- `matchMedia` 不可用：系统主题逻辑回退为浅色
- 非法偏好值：自动纠正为默认值

## 14. 测试策略

本项目当前没有现成测试基础设施，本次采用“两层验证”：

### 14.1 代码层最小验证

新增对 `preferences` 规范化逻辑的纯函数测试，前提是项目补充轻量测试运行环境。

如果本轮不引入测试框架，则至少保证：

- 偏好枚举和规范化逻辑拆到纯函数文件
- 逻辑足够集中，便于后续补测

### 14.2 手动验证

至少验证以下场景：

1. 首次打开页面，显示默认偏好
2. 切换浅色、深色、跟随系统后，刷新页面仍保持
3. 调整字体大小滑块后，刷新页面仍保持
4. 语言模式切换后，刷新页面仍保持
5. 面板可通过按钮打开关闭
6. 点击面板外区域可关闭
7. 按 `Esc` 可关闭
8. 登录页、首页、至少一个功能页都能受到偏好影响
9. 移动端宽度下，悬浮按钮不遮挡主要交互

## 15. 迭代顺序

建议按以下顺序实现：

1. 提取偏好常量、默认值、规范化函数
2. 建立 `PreferencesContext`
3. 在根节点接入 Provider
4. 完成主题和字体的 DOM/CSS 同步
5. 加入悬浮按钮和面板 UI
6. 接入语言模式状态和说明文案
7. 调整全局样式适配暗色主题
8. 构建和手动验证

## 16. 风险与取舍

风险：

- 项目里大量 `px` 字号不会完全随字体模式缩放
- 现有 `App.css` 中存在较多硬编码浅色背景，暗色主题第一版可能无法覆盖每一个细节
- 语言模式首期不会立即带来完整双语页面

取舍：

- 本轮优先建立可扩展的全局偏好基础设施
- 暗色主题先保证主要路径可用，再逐页细化
- 语言模式先建能力再逐步翻译内容

## 17. 成功标准

- 任意页面都能打开全局控制面板
- 主题、字体大小、语言模式都能持久化
- 深色主题下主要页面结构清晰可读
- 设置不依赖登录状态
- 新能力不会破坏现有路由和认证流程
