# 考研计划详情页补齐设计

日期：2026-06-14

## 1. 背景

当前 `frontendv2` 的考研计划详情页已经接上了后端计划与打卡接口，但与旧 `frontend` 的 `StudyPlanDetailPage` 相比仍有明显缺口。

旧版页面的核心不是简单展示计划与打卡列表，而是一套完整的“按天查看 - 今日打卡 - 统计回看 - 编辑计划”的工作流。当前 `frontendv2` 版本只有：

- 顶部计划摘要
- 时间线式打卡记录
- 右栏常驻打卡表单
- 右栏常驻计划编辑表单

这与旧版相比缺失了最关键的体验：

1. 月历式打卡总览
2. 当天状态与按日查看
3. 连续打卡天数 / 总打卡天数 / 计划总时长 / 总打卡时长
4. 只允许“今天”打卡的旧版行为
5. 弹窗式打卡与弹窗式编辑计划

用户已经明确要求：

- 以旧 `frontend` 与当前后端真实实现为准
- 功能路线完整追平旧版
- 但不要直接照搬旧版页面布局和视觉组织
- 非必要不改后端

## 2. 目标

本次设计只针对 `frontendv2` 的考研计划详情页：

- 路由：`/station/kaoyan/plans/:planId`
- 页面：`frontendv2/src/pages/student/kaoyan/KaoyanPlanDetailPage.jsx`

目标：

1. 补齐旧版计划详情页的完整功能路线
2. 用 `frontendv2` 的页面语言重做布局，不复刻旧版视觉
3. 在不改后端接口的前提下，恢复按日历工作的主交互
4. 让页面职责更清晰，避免继续把逻辑堆进单一页面组件

非目标：

1. 不改计划列表页的功能边界
2. 不重构后端学习计划接口
3. 不新增后端统计接口
4. 不把打卡规则改成比旧版更宽松

## 3. 旧新版差距

旧版入口：

- 路由：`/kaoyan/plan/:id`
- 页面：`frontend/src/pages/kaoyan/StudyPlanDetailPage.jsx`

新版入口：

- 路由：`/station/kaoyan/plans/:planId`
- 页面：`frontendv2/src/pages/student/kaoyan/KaoyanPlanDetailPage.jsx`

当前差距主要在以下几类：

### 3.1 页面结构差距

旧版以“统计 + 月历 + 当日记录 + 弹窗动作”为主。

新版以“时间线 + 右栏表单”为主。

### 3.2 数据使用差距

旧版详情页围绕 `plan + checkIns` 做前端派生：

- 打卡日期集合
- 当日记录
- 日期状态
- 月历天格

新版只把 `checkIns` 当成一条普通记录流，没有真正形成按天视图。

### 3.3 交互规则差距

旧版只允许对“今天”进行打卡，过去日期只可查看，未来日期只做状态提示。

新版右栏表单允许直接改日期，已偏离旧版行为。

## 4. 功能映射

本次重构后的 `frontendv2` 计划详情页需要完整承接旧版功能：

- 旧版“计划顶部操作” -> 新版“PageIntro + 页面头部动作”
- 旧版“统计卡” -> 新版“摘要卡 + 进度条”
- 旧版“月历打卡板” -> 新版“主区月历工作台”
- 旧版“选中日期查看记录” -> 新版“当日记录面板”
- 旧版“打卡弹窗” -> 新版“打卡弹窗”
- 旧版“编辑计划弹窗” -> 新版“编辑计划弹窗”
- 旧版“删除打卡 / 删除计划确认” -> 新版“继续保留确认流程”

## 5. 页面结构设计

页面采用“主区工作台 + 右栏辅助区”的新版结构，但主交互回归旧版路线。

### 5.1 主区

主区包含四段：

1. 页面引导区
   - 面包屑：`考研主站 / 计划轨道 / 当前计划`
   - 标题：计划名称
   - 副标题：计划说明
   - 动作：`返回计划列表`、`编辑计划`、`删除计划`

2. 统计摘要区
   - 连续打卡天数
   - 总打卡天数
   - 计划总时长
   - 总打卡时长
   - 完成率进度条

3. 月历工作台
   - 当前月份标题
   - 上月 / 下月切换
   - 周视图表头
   - 日期格
   - 图例说明

4. 当日记录面板
   - 当前选中日期
   - 日期状态标签
   - 当日记录列表
   - 今日才展示的 `打卡` 按钮

### 5.2 右栏

右栏不再承载常驻编辑表单，改为辅助信息区：

1. 当前计划区间
2. 当前选中日期摘要
3. 打卡规则说明
4. 快捷返回计划列表

右栏的目标是补充上下文，不抢主区的按日历工作流。

## 6. 统计与数据来源

本次坚持“非必要不改后端”，继续只使用现有接口：

- `studyPlanApi.planDetail(planId, token)`
- `studyPlanApi.checkIns(planId, token)`
- `studyPlanApi.addCheckIn(planId, payload, token)`
- `studyPlanApi.updatePlan(planId, payload, token)`
- `studyPlanApi.deletePlan(planId, token)`
- `studyPlanApi.deleteCheckIn(checkInId, token)`

页面初始化继续并行拉取：

- `planDetail`
- `checkIns`

### 6.1 前端派生数据

为了完整恢复旧版功能，页面需要在前端派生这些值：

1. `checkedDates`
   - 已打卡日期集合

2. `checkedDays`
   - 唯一打卡日期数

3. `totalCheckedHours`
   - 所有打卡时长累计值

4. `streak`
   - 连续打卡天数

5. `dayCheckIns`
   - 当前选中日期对应的全部打卡记录

6. `selectedDayStatus`
   - 当前选中日期状态

7. `calendarDays`
   - 当前月历渲染需要的天格数组

### 6.2 后端字段复用策略

如果后端 `planDetail` 已返回这些值：

- `completionRate`
- `streak`
- `checkedDays`
- `plannedDurationHours`
- `totalDurationHours`

则优先使用后端值。

若缺失，则前端必须能够兜底计算，保证旧版页面的关键指标不丢失。

## 7. 日期状态规则

日期状态必须沿用旧版逻辑，不引入新规则。

### 7.1 状态类型

- `out`
  超出计划区间

- `checked`
  该日期已有至少一条打卡记录

- `today`
  该日期是今天，且今天尚未打卡

- `missed`
  该日期处于计划区间内，早于今天，且没有打卡记录

- `future`
  该日期晚于今天，且处于计划区间内

### 7.2 使用方式

- `out`：不可点击或点击后不展示打卡动作
- `checked`：可查看该日记录
- `today`：可查看该日记录，且显示 `打卡` 按钮
- `missed`：可查看该日空状态，但不可补打卡
- `future`：可查看状态，但不可打卡

## 8. 打卡交互设计

### 8.1 入口规则

用户点击月历日期格，只做两件事：

1. 选中该日期
2. 刷新下方“当日记录面板”

只有当选中日期状态为 `today` 时，才显示 `打卡` 按钮。

### 8.2 打卡弹窗

点击 `打卡` 后，打开弹窗，而不是在右栏常驻表单中填写。

字段沿用旧版最小集合：

- 学习时长（小时）
- 备注

### 8.3 校验规则

沿用旧版打卡校验：

1. 学习时长必填
2. 学习时长必须大于 `0`
3. 学习时长必须小于 `24`

不新增更复杂的跨日、重复打卡限制。

### 8.4 提交成功后的行为

提交成功后：

1. 关闭弹窗
2. 清空打卡表单
3. 重新拉取 `planDetail + checkIns`
4. 保持当前选中日期仍为今天
5. 让当日记录面板立即显示最新结果

## 9. 编辑计划交互设计

### 9.1 编辑入口

页面头部提供 `编辑计划` 按钮，点击后打开“编辑计划”弹窗。

### 9.2 编辑字段

字段沿用旧版：

- 计划名称
- 计划简介
- 开始日期
- 结束日期
- 计划总时长

### 9.3 校验规则

保留旧版最小校验：

1. 名称必填
2. 开始日期必填
3. 结束日期必填
4. 计划总时长必填

额外补一条轻量前端校验：

- 结束日期不得早于开始日期

这条校验不改变旧版路线，只是避免明显无效输入。

## 10. 删除行为

### 10.1 删除计划

继续保留确认步骤：

1. 用户点击 `删除计划`
2. 弹出确认
3. 确认后调用 `studyPlanApi.deletePlan`
4. 成功后返回 `/station/kaoyan/plans`

### 10.2 删除打卡

当日记录中的每条打卡记录继续保留 `删除`。

流程沿用旧版：

1. 点击删除
2. 弹出确认
3. 确认后调用 `studyPlanApi.deleteCheckIn`
4. 重新加载页面数据

## 11. 组件拆分建议

为避免 `KaoyanPlanDetailPage.jsx` 持续膨胀，本次建议拆分为以下单元：

### 11.1 页面编排层

- `KaoyanPlanDetailPage.jsx`

职责：

- 数据拉取
- 页面级状态协调
- 弹窗开关
- API 动作提交

### 11.2 月历工作台组件

- `KaoyanPlanCalendarCard.jsx`

职责：

- 月份切换
- 日期状态着色
- 日期格点击
- 图例展示

### 11.3 当日记录组件

- `KaoyanPlanDayPanel.jsx`

职责：

- 当前选中日期展示
- 状态标签
- 当日记录列表
- 删除记录入口
- 今日打卡按钮

### 11.4 弹窗组件

- `KaoyanPlanCheckInModal.jsx`
- `KaoyanPlanEditModal.jsx`

职责：

- 表单输入
- 表单校验提示
- 提交 / 取消动作

### 11.5 数据 helper

建议在 `frontendv2/src/pages/student/kaoyan/kaoyanPageData.js` 中补充：

- `buildPlanCalendarDays`
- `getPlanDayStatus`
- `buildPlanDetailMetrics`
- `groupCheckInsByDate`

这样页面组件可以聚焦渲染与编排，不直接承接所有日期计算逻辑。

## 12. 预览与降级

继续沿用 `frontendv2` 现有三态策略：

- preview
- remote
- fallback

### 12.1 预览模式

预览模式下：

- 月历可正常展示
- 统计可正常展示
- 当日记录可正常展示
- 编辑、删除、打卡动作继续禁用或仅给出提示

不能假装写入成功。

### 12.2 远端失败

远端失败时回退到预览数据，但页面结构不能退化回旧的时间线表单模式。

也就是说：

- 失败时仍然展示新月历版详情页
- 只是数据源切换为 preview

## 15. 设计结论

本次计划详情页补齐采用以下最终方案：

- 功能路线完整追平旧版 `StudyPlanDetailPage`
- 行为规则照搬旧版，尤其是“只允许今天打卡”
- 不改后端接口
- 不照搬旧版页面布局
- 使用 `frontendv2` 的主区工作台 + 右栏辅助区结构
- 用组件拆分和 helper 计算控制复杂度

这是一版“旧版工作流完整回归，新版信息架构重新组织”的计划详情页设计。
