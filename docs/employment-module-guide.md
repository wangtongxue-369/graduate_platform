# 就业模块使用文档

本文档说明就业模块当前已实现的用户功能、管理员功能、推荐与提醒逻辑、测试结果和已知问题。就业模块覆盖招聘会浏览、网申链接、在线简历、岗位推荐、投递进度跟踪，以及管理员端就业源数据维护。

## 入口与账号

- 普通用户入口：`/job`
- 管理员入口：`/admin/employment`
- 真实就业测试用户：`job@graduate.local` / `job1234`
- 管理员测试用户：`admin@graduate.local` / `admin123`

文件上传依赖腾讯云 COS。上传简历附件前，后端启动环境需要配置：

```bash
COS_SECRET_ID=真实SecretId
COS_SECRET_KEY=真实SecretKey
```

未配置时，简历附件上传会返回“文件服务未配置，请联系管理员设置 COS 凭证”。

## 普通用户功能

### 1. 就业功能面板

路径：`/job`

用户进入就业方向后，可以看到四个核心入口：

- 招聘会与网申入口：进入 `/job/fairs`
- 在线简历：进入 `/job/resume`
- 算法岗位推荐：进入 `/job/recommend`
- 投递进度跟踪：进入 `/job/applications`

### 2. 招聘会与网申入口

路径：`/job/fairs`

用户可以：

- 按城市、行业、关键词筛选招聘会。
- 选择是否显示过期招聘会。
- 查看招聘会标题、企业、行业、地点、开始时间、网申截止时间和状态。
- 进入招聘会详情页 `/job/fairs/:id`。
- 在招聘会未截止且存在申请链接时，点击“打开申请链接”跳转外部网申地址。
- 保存就业提醒偏好，包括城市、行业、岗位、薪资和企业类型。

提醒偏好用于管理员后续触发站内提醒时做匹配。当前站内提醒匹配主要使用城市、行业、岗位和企业类型；薪资保存为偏好信息，不参与提醒触发匹配，但会在岗位推荐中作为加分项。

### 3. 在线简历

路径：`/job/resume`

用户可以维护一份结构化在线简历：

- 目标岗位
- 期望城市
- 期望行业
- 期望薪资
- 最高学历
- 专业
- 技能关键词
- 项目关键词
- 实习关键词
- 证书/奖项
- 作品链接
- 基本信息
- 教育经历
- 项目经历
- 实习经历
- 技能特长
- 自我评价

这些结构化字段会被岗位推荐用于软匹配排序。推荐页里的手动筛选条件优先级更高，会先作为硬过滤；简历内容只对过滤后的岗位加分，不会覆盖用户在推荐页主动填写的筛选条件。

用户还可以上传一个当前有效的简历附件：

- 支持格式：PDF、DOC、DOCX
- 大小限制：默认最大 10MB
- 上传新附件会替换当前附件
- 下载附件走后端鉴权接口
- 删除附件只删除当前附件元数据和对象存储文件，在线文本简历保留

在线简历字段支持页面内切换编辑/预览，并可直接导出：

- 导出 Word：`GET /api/job/resume/export?format=docx`
- 导出 PDF：`GET /api/job/resume/export?format=pdf`
- 导出前前端会先保存当前在线字段，导出内容来自结构化在线简历，不依赖上传的附件文件。
- 导出接口必须登录后访问，文件名由用户名称和导出时间生成。

安全边界：

- 前端不展示 COS 对象 key、签名 URL 或公开直链。
- 管理员端也只能查看附件安全元数据，不能下载、替换或删除学生附件。

### 4. 算法岗位推荐

路径：`/job/recommend`

用户可以：

- 默认查看全部启用岗位。
- 按关键词、城市、行业、岗位类型、企业类型、学历要求、专业关键词、技能标签、薪资范围和“只看可直接投递”刷新推荐。
- 查看匹配岗位列表、匹配分和匹配原因。
- 进入岗位详情页 `/job/postings/:id`。
- 点击“加入投递跟踪”，跳转到 `/job/applications` 并预填岗位信息。
- 点击“打开申请链接”，跳转外部投递地址。
- 查看站内就业提醒，并支持标记已读或删除单条提醒。

推荐当前是不调用外部模型或招聘平台的本地确定性混合算法。它不是单一加权规则，而是把用户画像和岗位画像做文本相似度计算，再结合偏好、时效和可投递状态排序。推荐流程是：

1. 只读取启用岗位。
2. 如果用户填写了推荐页筛选条件，先按关键词、城市、行业、岗位类型、企业类型、学历、专业、技能、薪资和“只看可直接投递”做硬过滤。
3. 将用户账号专业、保存的求职偏好、在线简历结构化字段和当前筛选条件合并为用户画像 token。
4. 将岗位标题、企业、城市、行业、企业类型、岗位类型、薪资、学历、专业关键词、技能标签和描述合并为岗位画像 token。
5. 对过滤后的岗位计算 TF-IDF 余弦相似度和 BM25 文本相关度，并叠加结构化偏好软匹配、发布时间衰减和可直接投递信号。
6. 按最终匹配分倒序展示。

评分来源包括：

- TF-IDF 余弦相似度：衡量用户画像 token 与岗位画像 token 的整体相似度。
- BM25 文本相关度：突出关键词在岗位文本中的相关性，适合用户填写明确岗位、技能或行业关键词时排序。
- 结构化偏好软匹配：城市、行业、岗位类型、企业类型、学历、专业、技能和薪资只在用户实际填写了对应信号时参与评分。
- 发布时间衰减：近期发布岗位获得额外时效分。
- 外部申请链接：存在可直接投递链接的岗位获得额外可投递分。

匹配理由会展示在岗位卡片中，例如“简历与岗位画像相似”“岗位文本相关度高”“求职偏好匹配”“近期发布岗位”“可直接投递”等。

注意：上传的 PDF/DOC/DOCX 附件当前只作为文件保存和下载，不会被自动解析。岗位推荐使用的是在线简历文本字段。

站内提醒接口：

- 列表：`GET /api/job/notifications`
- 标记已读：`PUT /api/job/notifications/{id}/read`
- 删除提醒：`DELETE /api/job/notifications/{id}`

删除提醒只允许删除当前登录用户自己的提醒；删除后列表总数和未读数会随接口结果重新计算。

### 5. 岗位详情

路径：`/job/postings/:id`

用户可以查看：

- 岗位名称
- 公司
- 城市
- 行业
- 企业类型
- 岗位类型
- 薪资范围
- 学历要求
- 专业关键词
- 技能标签
- 岗位描述

用户可以从岗位详情：

- 加入投递跟踪
- 打开外部申请链接
- 返回岗位推荐

注意：当前“加入投递跟踪”不是平台内自动投递简历，只是创建或预填个人投递跟踪记录。

### 6. 投递进度跟踪

路径：`/job/applications`

用户可以：

- 新增投递记录。
- 编辑投递记录。
- 删除投递记录。
- 维护投递状态。
- 维护岗位快照、投递渠道、联系人、面试轮次、面试方式、面试地点/会议链接、期望薪资、Offer 薪资和失败/拒绝原因。
- 设置投递时间、下一步时间和最后跟进时间。
- 查看当前简历附件状态，并下载当前附件。

投递状态包括：

- 待投递
- 已投递
- 简历筛选中
- 笔试
- 一面
- 二面
- HR 面
- 终面
- Offer
- 已接受
- 已拒绝
- 未通过
- 已撤回
- 已关闭

如果从岗位详情或推荐列表进入，页面会自动带入：

- 关联岗位 ID
- 公司名
- 岗位名称
- 城市、行业、企业类型、岗位类型、薪资范围、学历要求、专业关键词、技能标签和申请链接

后端创建投递记录时，如果传入 `jobPostingId`，会读取对应岗位并写入岗位快照字段。后续更新同一条投递记录时，未显式传入的快照字段默认保留历史值；只有切换到新的关联岗位时，才会用新岗位信息刷新快照。岗位后续被管理员修改时，已有投递记录仍保留创建或编辑时的快照。投递记录还会保存当时使用的简历附件文件名，便于追溯用户投递时选择的材料。

## 管理员功能

### 1. 就业管理工作台

路径：`/admin/employment`

管理员可以在一个页面内切换三个管理对象：

- 招聘会管理
- 岗位管理
- 简历附件状态

页面顶部显示：

- 招聘会总数
- 启用招聘会数
- 岗位总数
- 启用岗位数
- 已上传简历附件数

### 2. 招聘会管理

路径：`/admin/employment`，切换到“招聘会管理”

管理员可以：

- 新增招聘会
- 编辑招聘会
- 删除招聘会
- 设置启用或停用
- 触发招聘会匹配提醒
- 按关键词和状态筛选招聘会
- 分页查看招聘会列表

招聘会字段包括：

- 标题
- 企业
- 城市
- 行业
- 目标岗位
- 地点
- 开始时间
- 结束时间
- 网申截止时间
- 申请链接
- 展示状态
- 描述

校验规则：

- 标题和企业必填。
- 结束时间不能早于开始时间。
- 申请链接必须是 `http` 或 `https`。
- 相同标题、公司、地点和申请链接的招聘会不能重复创建。

### 3. 岗位管理

路径：`/admin/employment`，切换到“岗位管理”

管理员可以：

- 新增岗位
- 编辑岗位
- 删除岗位
- 设置启用或停用
- 触发岗位匹配提醒
- 按关键词和状态筛选岗位
- 分页查看岗位列表

岗位字段包括：

- 岗位名称
- 企业
- 城市
- 行业
- 企业类型
- 岗位类型
- 薪资范围
- 学历要求
- 专业关键词
- 技能标签
- 申请链接
- 展示状态
- 岗位描述

校验规则：

- 岗位名称和企业必填。
- 申请链接必须是 `http` 或 `https`。
- 删除已被投递记录引用的岗位时，后端会改为停用，保留历史关联。

### 4. 简历附件状态

路径：`/admin/employment`，切换到“简历附件状态”

管理员可以只读查看：

- 用户姓名、邮箱、学号
- 学校、专业
- 是否已上传当前简历附件
- 文件名
- 文件大小
- 文件类型
- 上传时间

管理员不能：

- 下载学生简历附件
- 上传或替换学生简历附件
- 删除学生简历附件
- 查看 COS key 或对象存储 URL

### 5. 触发站内提醒

管理员可在招聘会或岗位卡片上点击“触发提醒”。

触发逻辑：

- 招聘会提醒会根据招聘会城市、行业和目标岗位匹配用户偏好。
- 岗位提醒会根据岗位城市、行业、岗位类型和企业类型匹配用户偏好。
- 同一用户对同一招聘会或岗位已有提醒时，会跳过重复提醒。
- 生成的提醒会在用户 `/job/recommend` 页面显示。

## 已知问题与待完善项

### 1. 岗位推荐不去重

推荐接口直接读取所有 `active=true` 岗位并逐条打分。如果数据库中存在重复岗位，前端会显示重复卡片。

建议：

- 在后台新增岗位时做重复校验。
- 在初始化逻辑中清理历史重复岗位。
- 推荐接口按 `title + companyName + city + applyUrl` 做兜底去重。

### 2. 岗位管理缺少重复校验

招聘会管理已有重复校验，但岗位管理目前只校验必填和申请链接格式，没有校验同公司同岗位重复。

建议：

- 新增 `title + companyName + city + applyUrl` 级别的重复校验。
- 对历史重复数据提供一次性清理或停用策略。

### 3. 投递记录重复只在前端提示

投递跟踪页会在前端检测重复岗位并弹窗确认，但后端没有唯一约束。直接调用接口或并发提交仍可能创建重复投递记录。

建议：

- 对同一用户同一 `jobPostingId` 增加后端校验。
- 对手工补录记录按标准化后的公司名和岗位名做软校验。

### 4. 投递记录没有完整简历版本快照

当前投递记录会保存岗位快照和使用的附件文件名，但不会复制完整在线简历字段，也不会保存附件大小、类型、上传时间等完整附件元数据。用户后续大幅修改在线简历后，仍无法还原当时投递的完整简历文本。

建议：

- 增加简历版本表，保存每次投递使用的在线简历字段快照。
- 在投递记录中保存当时的附件大小、类型、上传时间。
- 如要实现真正的平台内投递，应新增“提交简历到岗位”的服务端动作，而不是只记录跟踪。

### 5. 关联岗位允许指向停用岗位

投递记录保存 `jobPostingId` 时，只校验岗位存在，不校验岗位是否启用。对于手工补录历史投递可以接受，但对于从平台岗位发起的投递语义不够严格。

建议：

- 区分“手工补录投递”和“从平台岗位加入跟踪”。
- 平台岗位加入跟踪时要求岗位仍为启用状态。

### 6. 状态流转没有历史记录

投递记录只有当前状态，没有状态变更时间线。用户无法看到从已投递到面试、录用或拒绝的完整过程。

建议：

- 新增投递状态事件表，记录状态、时间、备注和操作来源。

### 7. 管理员删除招聘会会硬删除

招聘会删除当前为直接删除。如果该招聘会已经触发过站内提醒，提醒中的详情链接可能指向不存在的数据。

建议：

- 对已触发提醒或已有引用的招聘会改为停用。
- 或在提醒详情跳转时处理已删除状态。

### 8. 提醒依赖用户主动保存偏好

管理员触发提醒时，只遍历已启用的用户偏好。没有保存偏好的就业用户不会收到提醒。

建议：

- 在用户首次进入就业模块时引导保存偏好。
- 或对没有偏好的就业用户提供兜底提醒策略。

### 9. 简历附件不会自动解析

当前推荐逻辑读取在线简历结构化字段，不解析上传的 PDF/DOC/DOCX 附件。如果用户只上传附件但不维护在线文本字段，附件内容不会参与岗位推荐。

建议：

- 后续增加附件文本抽取任务，将技能、项目、实习关键词回填到在线简历字段。
- 在简历页提示用户维护结构化字段，避免误以为上传附件即可参与推荐。

### 10. 附件上传依赖外部 COS 配置

本地或演示环境未配置 COS 时，简历附件无法上传。当前错误提示清晰，但演示前需要提前配置环境变量并重启后端。

建议：

- 在开发环境提供本地文件存储 profile。
- 或在管理员首页显示文件服务配置状态。
